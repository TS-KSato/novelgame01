# ゼルグの旅人

恐怖で保たれた世界を、信頼で変えられるか。六つの結末を辿る、日本語のノベルゲームです。

主人公は旅を続けながら、出会う人々と関わります。選ぶ言葉と行動によって、物語は六つの結末のいずれかへ向かいます。

- 形式：静的な Web ページ（ビルド工程なし）。ブラウザだけで遊べます
- 対応：スマートフォンの**横向き専用**です。縦向きでは案内が表示され、物語は進みません

## 公開先

- 公開 URL：<https://ts-ksato.github.io/novelgame01/>
- 公開元：GitHub Pages。`main` ブランチのリポジトリ直下を公開しています

## 対応環境

- **iPhone 17 の Safari と Chrome** で、主要な操作を確認しています。
- **Android の実機**では確認していません。
- 上記以外の機種・OS・ブラウザでの動作は保証していません。
- 開発中の確認は、デスクトップ版 Chromium で行っています。

## プレイ方法

### 始める・続ける

- **物語をはじめる**：確認なしで最初から始まります。自動セーブの内容は、新しい進行に置き換わります（[保存の仕様](#保存の仕様)）。
- **つづきから**：自動セーブの位置から再開します。読み込めない場合は、理由が表示されます。
- **記憶の書庫**：到達した結末の数と、到達した結末の内容を確認できます。未到達の結末は伏せられています。
- **CG 鑑賞**：解放済みの CG を一覧し、拡大して見られます。
- **設定・セーブ**：文字の速さ、音量、手動セーブ（3 枠）、読込、セーブコードの書き出しと復元。

### 文章を読む

- 文章欄をタップすると、文章が進みます。キーボードでは Space または Enter で進みます。
- 文章が表示されている途中でタップすると、表示を完了します。もう一度タップすると次へ進みます。
- **AUTO**：文章を自動で進めます。選択肢がある行に達すると、選択肢を表示して止まります。
- **既読 SKIP**：読んだことのある文章を、表示を省いて進めます。未読の文章と、選択肢がある行で止まります。
- **履歴**：これまでの文章を読み返せます。
- **断片**：旅の中で見つかった記憶の断片と、登場人物との関係の度合いを確認できます。
- **SAVE / MENU**：手動セーブと、タイトルへ戻る操作があります。

### 選択肢

- 選択肢は、表示された後に行った、ポインター（タップ・クリック）またはキーの押下で決まります。
- AUTO や既読 SKIP で選択肢が表示された場合、その操作を続けても選択は決まりません。

### 音声

- 画面上部の**音アイコン**で、すべての音声を入／切できます。初期状態は「切」です。
- **設定・セーブ** の「音声」では、BGM、環境音、効果音の音量を別々に調整できます。
- 参考音は、**環境音と効果音のスライダー**を離したときに鳴ります。BGM のスライダーでは鳴りません。
- 「文字の速さ」は、文章の表示速度です。

### CG 鑑賞

- 「物語の場面」と「旅のひとこま」の二つのタブがあります。
- 解放されていない CG は、鍵の表示になり、題名も画像も表示されません。
- 拡大表示では、画像をタップすると題名と操作欄の表示が切り替わります。「一覧へ戻る」で一覧に戻ります。

### ホーム画面への追加と全画面表示

- タイトル画面の「全画面で開く」は、ブラウザが全画面表示に対応している場合に表示されます。
- ホーム画面に追加すると、ブラウザの操作欄なしで起動できます。タイトル画面の「ブラウザの操作欄なしで遊ぶ」から、iPhone での追加手順を確認できます。
- ホーム画面から起動したアプリは、Safari とは別の保存領域を使います。

## 保存の仕様

すべての保存は、プレイしているブラウザの中（localStorage）に行われます。アプリからサーバーへは送信されません。

| データ | 保存先 | 内容 |
|---|---|---|
| 進行、既読、結末、手動セーブ、設定 | `zelg-v1` | 手動セーブ 3 枠、自動セーブ、既読、到達した結末、文字の速さ、音声設定 |
| CG 解放 | `zelg-gallery-v1` | 解放済みの CG の名前だけ |
| 版の移行前のバックアップ | `zelg-v1-backup-full-v20` | 版の移行の際に、移行前の `zelg-v1` の内容を一度だけ保存します |

- **手動セーブ**：3 枠。上書きする前に確認が出ます。
- **自動セーブ**：場面が進むたびに更新されます。「つづきから」はこの内容を使います。
- **既読**：読んだ文章の記録。既読 SKIP に使います。古い版の保存は、版ごとの移行処理で現行の文章へ移します。
- **結末**：到達した結末の記録。「記憶の書庫」に表示されます。
- **CG 解放**：一度解放された CG は外れません。
- **設定**：文字の速さ、音声の入／切、音量（BGM、環境音、効果音）。

### 「物語をはじめる」で変わるもの・残るもの

- **変わる**：自動セーブ（つづきから）の内容。
- **残る**：手動セーブ 3 枠、既読、結末、CG 解放、設定。

### セーブコードの書き出しと復元

- **設定・セーブ** から、書き出し時点の進行、既読、結末を、テキストの「セーブコード」として書き出せます。コードは `ZELG1.` で始まります。
- 復元では、コードの形式と内容を確認してから読み込みます。内容が正しくない場合、保存データは変わりません。
- 復元すると、取り込んだ進行で現在の進行が置き換わります。既読と結末は、既存の記録に加えて統合されます。手動セーブ 3 枠は変わりません。
- 取り込んだ進行で読んだ場面に対応する CG が、新たに解放されることがあります。解放が取り消されることはありません。
- セーブコードは、アプリから外部へ送信されません。他の人に渡す場合は、内容を理解したうえで扱ってください。

### 注意

- ブラウザのサイトデータや閲覧履歴を消去すると、保存は失われます。大切な進行は、事前にセーブコードを書き出してください。
- 保存は、同じブラウザ・同じ端末の中だけで使われます。別のブラウザや端末へ移すには、セーブコードを使ってください。
- ブラウザの保存が使えない環境では、保存できないことが画面に表示されます。
- 保存はクラウドには同期されません。

## 開発を始める

### 必要なもの

- Git
- 静的ファイルを配信できる HTTP サーバー（例：Python 3 の標準の `http.server`）
- Chromium などの最新のブラウザ
- 対応表の再生成に使う場合のみ、Node.js

このリポジトリには `package.json` がありません。`npm install` やビルドの手順はありません。

### ローカルでの起動

リポジトリの直下で、HTTP サーバーを起動します。

```sh
python3 -m http.server 8000
```

ブラウザで `http://localhost:8000/` を開きます。`file://` で開くと、音声ファイルの読み込み（fetch）が制限されるため、HTTP サーバーで開いてください。

| ファイル | 役割 |

| `story.js` | 本文の正本。場面、行、話者、分岐、選択肢、行 ID（`PAGE_IDS`） |
| `app.js` | 進行、表示、保存、既読、セーブコード、版の移行 |

## 本文を変更するとき

本文の変更は、保存と既読に直接関わります。次の要点を守り、詳細は [docs/CONTENT-CHANGES.md](docs/CONTENT-CHANGES.md) の手順に従ってください。

### 現在の版

- 本文の版（保存の版）は、`app.js` の `OPENING_REV` で定義されています。現在は `full-v20` です。
- 保存は、場面の名前と行番号、そして版の名前を記録します。

### 変更の種類と扱い

| 変更の種類 | 既読の扱い | 版 | 必要な作業 |
|---|---|---|---|
| 空白・改行だけの変更 | 維持 | 上げない | 表示の確認 |
| 話者または本文の文字が変わる（句読点や言葉の修正を含む） | **その行の既読は解除されます**。変わった文章を既読として引き継ぎません | 上げる | 版の手順（下記） |
| 行を追加・削除・並べ替える | 行の位置が変わるため、保存と既読を移す必要があります | 上げる | 版の手順と、背景・立ち絵の行番号の更新 |

- 既読は、行 ID が同じで、話者と本文（空白を除く）が一致する行だけ引き継がれます。文字が一つでも変わると、その行の既読は解除されます。
- 文字の変更を既読に反映するには、版を上げる必要があります。版を上げずに文字を変えると、既読は古い文章のまま残ります。
- どの変更でも、既読を解除するかどうかは作者が判断してください。

### 版を上げるときの作業

1. 変更の前の状態（直前のコミット）を、`tools/make-seen-map.js` の `REVS` に、直前の版の名前で登録します。
2. `app.js` の `OPENING_REV` を新しい版の名前にします。
3. 直前の版の保存を新しい版へ写す処理を、`app.js` の `migrateState` に追加します。行の位置が変わらない場合も、直前の版を新しい版へ写す処理は必要です。これがないと、直前の版の保存は読み込めなくなります。
4. `node tools/make-seen-map.js --stats` で件数を確認し、`node tools/make-seen-map.js > seen-map.js` で対応表を再生成します。
5. 背景と立ち絵の行番号、CG・BGM・効果音・環境音の行 ID を確認します。
6. `index.html` の `seen-map.js` と `app.js` の `?v=` を上げます。

### 保存と既読の検証

- 直前の版の保存（手動セーブと自動セーブ）を読み込み、場面と行が意図どおりか確認します。
- 既読を持つ保存で既読 SKIP を使い、未読の変更文で止まることを確認します。
- 版を上げた後も、現在の版の保存が問題なく読み込めることを確認します。

## 技術的な注意

### 場面と行 ID

- 行は、場面の中の順番（行番号）と、行 ID の二つで管理されます。
- 行 ID は `story.js` の `PAGE_IDS` にあり、本文と同じ数だけあります。
- CG、BGM、効果音、環境音は行 ID で指定されているため、行番号が変わっても同じ行を指します。
- 背景と立ち絵は行番号の範囲で指定されています。行を追加・削除したら、これらを手で更新してください。

### キャッシュ

- ブラウザは同じ URL のファイルを保存して再利用します。変更したファイルを読み込み直させるため、`index.html` の script と link の `?v=` を上げます。
- 背景の画像は、`backgrounds.js` の `BG_VERSION` で一括して更新します。
- CG の画像は、`cg.js` の各定義の `?v=` で更新します。

## 公開とセキュリティ

### GitHub Pages

- `main` ブランチへの push で、GitHub Pages のビルドが実行されます。
- リポジトリ直下の `.nojekyll` は、Jekyll による処理を止めるために置かれています。
- 公開されるのは、リポジトリの追跡ファイルです。`.gitignore` で除外しているファイル（作業用の `.claude/` など）は公開されません。`tools/` と `docs/` も公開されます。
- 公開範囲の設定（公開するブランチ、カスタムドメイン、HTTPS の強制）は、リポジトリの Settings で管理されます。

### Content-Security-Policy（CSP）

本編の `index.html` には、次の CSP（`<meta http-equiv="Content-Security-Policy">`）が設定されています。

- `default-src 'self'`、`script-src 'self'`、`connect-src 'self'`、`img-src 'self'`、`manifest-src 'self'`：読み込みは同じオリジンのファイルに限ります。
- `style-src 'self' 'unsafe-inline'`：断片の画面は、関係の度合いを `style` 属性で示すため、この許可が必要です。
- `media-src 'none'`、`font-src 'none'`、`object-src 'none'`、`frame-src 'none'`、`worker-src 'none'`、`base-uri 'none'`、`form-action 'none'`：使っていない種類の読み込みを止めます。
- スクリプトには `unsafe-inline` も `unsafe-eval` も許可していません。

この CSP は `index.html` だけに設定されています。開発用プレビューには設定されていません。

meta タグでは、`frame-ancestors`（埋め込みの制限）、`report-uri`（違反の報告先）、`sandbox` を指定できません。これらの指定には、応答ヘッダーが必要です。GitHub Pages では、リポジトリからは応答ヘッダーを設定できません。

### 外部通信と保存データ

- 本編は、同じオリジンの素材ファイルだけを読み込みます。外部のサーバーへ通信しません。
- 保存データは、ブラウザの localStorage に保存されます。

### GitHub 側で管理するもの

- リポジトリの公開範囲、Pages の設定、ブランチの保護、アクセス権、2 段階認証。
- 応答ヘッダー（CSP 以外の HTTP ヘッダー、キャッシュの制御）。
