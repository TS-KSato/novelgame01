# ノベルゲーム制作キット（試作 0.1.0）

「ゼルグの旅人」の仕組みから、別の作品でも使える部分を取り出した試作です。短いサンプル作品 2 つで動作を確かめられます。

- 共通エンジン：`kit/engine/`
- サンプル作品：`kit/samples/sample-a/`（分岐・選択肢・背景・立ち絵・CG・音・保存を含む）と `kit/samples/sample-b/`（保存の分離を確かめるための最小の作品）
- 版の固定：`kit/releases/0.1.0/`
- 検証：`tests/`
- 共通と作品固有の分け方：[docs/kit/SPLIT.md](../docs/kit/SPLIT.md)

公開中のゼルグ（リポジトリ直下）は、この試作の影響を受けません。

## 1. 動かす

リポジトリの直下で、次を実行します。

```sh
node tests/lib/serve.js 8080
```

ブラウザで次を開きます（横向きで見てください）。

- http://127.0.0.1:8080/kit/samples/sample-a/index.html
- http://127.0.0.1:8080/kit/samples/sample-b/index.html

作品の画面は、横向きに固定して使います。縦向きでは案内を出して止まります。

## 2. 作品の構成

```
kit/samples/<作品ID>/
  index.html   キットを読み込み、window.KIT_GAME を起動する（ほぼ固定）
  game.js      作品データ（window.KIT_GAME）。作品の中身はここに書く
  assets/      画像・音声
```

`index.html` は次の形のままで使えます。`releases/0.1.0` の部分だけが、使うキットの版です。

```html
<link rel="stylesheet" href="../../releases/0.1.0/kit.css">
<div id="kit-root"></div>
<script src="../../releases/0.1.0/validate.js"></script>
<script src="../../releases/0.1.0/kit.js"></script>
<script src="game.js"></script>
<script>window.KIT = KitEngine.start(window.KIT_GAME);</script>
```

## 3. 新しい作品を作る

1. `kit/samples/sample-a/` を `kit/samples/<新しい作品ID>/` へ丸ごとコピーします（素材も含む）。
2. `game.js` の内容を、新しい作品のものに書き換えます。`id` は必ず新しい値にします（保存が混ざらないように）。
3. `kit` の欄は、使うキットの版（今は `0.1.0`）のままにします。
4. ブラウザで `index.html` を開き、起動を確かめます。作品データに誤りがあると、理由つきの画面が出て止まります。
5. 検証を実行します（第 6 節）。

サンプルの素材は試験用の単純な図形と音です。Zelg の素材は含まれず、複製もしていません。

## 4. 作品データに登録するもの

| 登録するもの | `game.js` の項目 | 書き方 |
|---|---|---|
| 文章 | `scenes.<場面>.lines` | `{ id: '行ID', speaker: '話者キー', text: '本文' }`。行IDは作品全体で一意 |
| 話者（名前） | `speakers` | `{ 話者キー: '表示名' }`。話者のない行は地の文 |
| 場面の名前 | `scenes.<場面>.title` | 画面上部に出る |
| 分岐（選択肢） | `scenes.<場面>.choices` | `{ text, to, set?, when? }`。`set` はフラグの設定、`when` は表示条件（関数） |
| 場面の移動 | `scenes.<場面>.next` | 次の場面名。フラグで決めるなら関数（`(flags) => ...`） |
| フラグ | `flags` | `{ 名前: { type: 'boolean', default: false } }` か `{ type: 'enum', values: [...], default }` |
| 背景 | `assets.backgrounds` と `cues`（`bg`） | 素材を登録し、行IDで指定 |
| 立ち絵 | `assets.portraits` と `cues`（`portrait`） | `{ slot: 'left'｜'right', char, expr }`。`{ slot, clear: true }` で消す |
| CG | `assets.cgs` と `cues`（`cg`） | `{ id, until? }`。`until` まで出し、到達で CG 鑑賞に解放 |
| BGM・環境音 | `assets.bgm`・`assets.ambience` と `cues` | 行IDで指定。同じ曲が続けば止めない |
| 効果音 | `assets.se` と `cues`（`se`） | 行に到達したときに一度だけ鳴る |
| 旧い行IDの対応 | `aliases` | `{ 旧ID: 新ID }`。行IDを変えたときだけ |

演出（`cues`）は、一つにつき「背景・BGM・環境音・効果音・立ち絵・CG」のどれか一つだけを書きます。

## 5. 保存と既読の互換

- **保存キー**は `kit:<作品ID>:v1` です。作品IDを変えると、別の作品として扱われます。
- **既読**は「行ID＋本文の指紋（空白を除いた話者と本文）」です。
  - 空白だけを直した行：既読のまま。
  - 文字（句読点や言葉）を直した行：その行だけ未読に戻ります。既読を保つには、版の変更と既読の移行が必要です。
  - 行を挿入・削除しても、行IDが同じなら、演出と既読はずれません。ただし、行IDそのものを変える場合は `aliases` が必要です。
- **作品データの版**（`dataVersion`）は、文章・行・演出を変えたら上げます。版が違う保存は、`aliases` で行IDを写してから読みます。写せない行の保存は読まれません（「この保存の位置は、現在の作品にありません」と出ます）。
- **キットの版**は保存に入ります。作品が固定した版と違う保存を読むときは、作品側で扱いを決めます（現在の試作では、版が違う作品は起動しません）。

行IDを使っても、保存の移行が不要になるわけではありません。文字を変えた行の既読や、行IDを変えたときの保存は、上の対応が必要です。詳しくは [SPLIT.md の第 8 節](../docs/kit/SPLIT.md#8-行idだけでは保存の移行は不要にならない) を参照してください。

## 6. 検証

リポジトリの直下で実行します。

```sh
node tests/run.js                # すべて
node tests/run.js unit           # 作品データの検証・演出の状態・行の挿入・eval 不使用（ブラウザ不要）
node tests/run.js browser        # サンプルA・Bを Chromium で動かす（Playwright が必要）
node tests/run.js zelg           # ゼルグの起動と、既読の対応表が履歴から作り直せること
```

- `browser` の試験は、選択肢を実際のマウス操作で選びます。プログラムからの `click()` で選ばれないことも確かめます。
- `zelg` の試験は、ゼルグのファイルを変えません。対応表の確認には git の履歴が必要です（浅いクローンでは失敗します）。

素材を作り直すとき：

```sh
node kit/tools/make-assets.js
```

## 7. キットの更新を作品へ取り込む

キットの版は、作品ごとに固定されています。新しい版を使うときは、作品の作者が次の手順で行います。

1. `node kit/tools/release.js` で、`kit/engine/` の変更を新しい版のフォルダ（`releases/<新しい版>/`）へ写します。`kit/engine/kit.js` の `KIT_VERSION` を先に上げます。既存の版のフォルダは上書きされません。
2. 作品の `index.html` の `releases/<古い版>/` を `releases/<新しい版>/` に書き換えます。
3. 作品の `game.js` の `kit` の欄を、新しい版にします。
4. 検証を実行し、作品を動かして確かめます。
5. 作品データの版（`dataVersion`）は、文章を変えていなければ上げなくてもかまいません。

共通エンジンを更新しても、既存の作品は自動では変わりません。

## 8. 現在の制限

- 試験はデスクトップ版 Chromium だけで行いました。iPhone・Android の Safari や Chrome では確かめていません。
- 音の再生は Web Audio に依存します。自動再生の制限のあるブラウザでは、最初の操作の後に鳴ります。
- 縦向きの扱いは、画面の向きの判定（`orientation: portrait`）に依存します。
- 素材は PNG と WAV（検証で使う単純な図形と音）だけです。ほかの形式は、`FILE_RE` の許可に加える必要があります。
- 版の移行の自動化（作品データを新しい版へ自動で写す仕組み）はありません。`aliases` は手で書きます。
- 旧版の作品データの移行表（ゼルグの `seen-map.js` に当たるもの）はキットにありません。必要な作品は、その作品で作ります。
- 場面を跨ぐ CG の区間は、同じ場面の中だけで指定できます。
- ゼルグの既存の本文・背景・立ち絵のテーブルを、キットの形式へ変換する作業は含みません。
- 作品の制作者向けの画面（エディタ）はありません。作品データは手で書きます。
- 設定画面は、文字の速さと三つの音量だけです。
- ゼルグの試験（`tests/zelg/`）は、起動と対応表だけを確かめます。ゼルグの旧版の保存を使った互換試験、およびゼルグの本編の操作の試験は、まだ移植していません。
